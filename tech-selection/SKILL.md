# 技术选型

目标：**直接做选择，不做技术百科。**

已有项目普通修改默认沿用现有技术栈；新项目、明确迁移或现有方案无法满足需求时再重新选型。

## 前端

| 场景 | 默认选择 | 偏离条件 |
|---|---|---|
| 普通 Web / 后台 / 管理系统 | React + TypeScript + Vite | 需要 SSR / SEO / 内容站能力时改用 Next.js |
| 桌面 GUI | React + TypeScript + Vite + Wails | 已有项目沿用现有前端；不因个人偏好主动换框架 |
| SSR / SEO / 内容站 | Next.js | 明确不需要 SSR / SEO 时使用 Vite SPA |
| 组件库 / 样式 / 视觉规范 | 跟随项目现状 | 新项目交给 `ui-style` |

前端默认不主动增加复杂状态管理、第二套 UI 体系或额外构建链。

## 后端

| 场景 | 默认选择 | 偏离条件 |
|---|---|---|
| Web API / 服务 | Go | AI / ML / 数据分析或关键 SDK 明显偏 Python 时用 Python |
| 桌面业务与控制层 | Go | Python 仅作为独立 Worker 提供其优势能力 |
| 正式 CLI / 跨平台工具 | Go | 内部脚本、一次性任务、数据或 AI 自动化时用 Python |
| 批处理 / 自动化 | Python | 单二进制分发、高并发、长期运行、部署一致性要求高时用 Go |
| 本地单机数据 | SQLite | 只有并发、规模或服务化需求明显超出时升级 |
| 服务端关系数据 | PostgreSQL | 只有明确约束时选择其他数据库 |
| 缓存 / 短期状态 / 限流 | 不默认引入 Redis | 出现真实共享缓存或状态需求时再加 |
| 大文件 / 媒体 / 归档 | 对象存储 | 只有文件规模或访问模式需要时引入 |
| 全文检索 | 不默认引入搜索引擎 | 全文检索成为核心能力时再加 |

桌面需要 Python 时，链路固定为：**前端 → Wails → Go → Python Worker**。Go 管理 Worker 生命周期；前端不直连 Python；正式分发不依赖用户预装开发用 Python 环境。

## 接口协议

| 需求 | 默认选择 |
|---|---|
| 普通 API | HTTP + JSON |
| 服务端单向实时推送 | SSE |
| 双向实时通信 | WebSocket |
| 高吞吐内部服务通信 | gRPC |
| 本地进程简单通信 | stdin/stdout + 结构化消息 |

没有明确收益时，不增加 GraphQL、gRPC、消息队列或额外协议层。

## 默认不要提前引入

**微服务 · Kubernetes · 消息队列 · Redis · GraphQL · gRPC · 第二种后端语言 · Python Worker · 复杂前端状态管理 · 多层架构模板**

只有当前需求已经产生明确收益时才引入，不为未来假设提前设计。

## 输出

只输出：**选择：** `<技术路线>`　**原因：** `<2~4 个关键原因>`　**偏离默认：** `<有则写，没有省略>`

只有两个方案会造成明显不同的产品结果、且需求无法判断时，才让用户选择；普通技术细节由 Agent 直接决定。
