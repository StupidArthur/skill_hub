# UI 风格约束

本 Skill 只定义**默认视觉方向和交互倾向**，不绑定前端框架、组件库、CSS 方案或固定设计 Token。

如果项目已有成熟设计系统、品牌规范或用户提供了明确参考，它们优先于本 Skill。

## 核心风格

默认方向：**浅色、克制、简洁、内容优先**。

- 大面积使用中性背景，避免纯白/纯黑造成过强对比；
- 一次界面只保留一个主要强调色，状态色按语义使用；
- 层级主要靠字号、字重、间距、边框和布局建立，而不是靠大量色块和阴影；
- 留白要足够，但工具型界面不要为了“高级感”牺牲信息效率；
- 组件外观统一，交互反馈清晰，不制造无意义的视觉差异。

## 布局与信息层级

1. **先内容后装饰**：先确定信息结构、主操作和阅读顺序，再处理视觉细节。
2. **减少容器套容器**：能靠分组、间距和标题表达层级时，不额外套卡片。
3. **主次明确**：一个区域通常只有一个主操作；次级操作降低视觉权重。
4. **工具界面优先效率**：表格、表单、列表、日志、配置页优先清晰和可扫读，不追求展示型留白。
5. **响应式按真实场景做**：不为了“响应式”强行把桌面工具设计成移动端页面。

## 视觉约束

### 默认使用

- 中性浅色背景 + 单一强调色；
- 轻边框、轻阴影或无阴影；
- 中等圆角，避免所有元素都做成大圆角胶囊；
- 系统字体或项目既有字体；
- 简短、自然的过渡动画，只用于状态变化和操作反馈。

### 默认避免

除非产品定位明确需要，否则不要默认使用：

- 大面积渐变；
- 玻璃拟态、霓虹发光、强模糊背景；
- 超大 Hero 标题和营销页式留白；
- 每个区块都做独立卡片；
- 过深阴影、过多浮层感；
- 装饰性 3D、无意义插画和动态图形；
- 为了“科技感”大量使用蓝紫渐变；
- 为了“高级感”降低文字对比度或缩小字号。

## 组件与交互

- 优先复用项目已有组件体系；没有时再选择成熟组件方案。
- 常见控件遵循用户熟悉的交互，不重新发明 Checkbox、Select、Dialog、Table 等基础模式。
- Hover、Focus、Disabled、Loading、Error 等状态必须可辨识。
- 动效保持短促，不阻塞操作；纯装饰动画能省则省。
- 危险操作必须与普通操作有明确区分，但不要靠夸张视觉制造压力。

## 设计流程

### ① 先识别场景

判断这是管理工具、生产力工具、内容产品、营销页、数据面板还是其他界面。已有设计系统优先沿用。

### ② 确定信息层级

先确定主任务、核心信息、主操作和次级操作，再决定布局。

### ③ 应用默认风格

没有明确品牌要求时使用本 Skill 的克制浅色方向；如果用户提供品牌、参考图或明确风格，则以用户要求为准。

### ④ 自检

完成界面后检查：

- 是否一眼看得出页面主任务；
- 是否存在无意义的卡片、颜色、阴影或装饰；
- 信息是否清晰可扫读；
- 操作状态是否完整；
- 是否为了视觉效果牺牲可用性。

**完成标志**：界面风格一致、信息层级清晰，且没有为了“好看”引入多余复杂度。
