# 交付与版本操作

> 流程阶段⑤。默认只汇报开发结果；提交、打包、发布等动作按用户要求执行。

## 交付说明

最终至少说明：

- 改了什么；
- 做了哪些验证及结果；
- 是否还有未验证项、已知限制或残余风险。

只有行为、接口、部署或使用方式发生变化时，才更新项目中已有的相关文档；不要为了流程完整额外制造文档。

## Git 安全

- 不覆盖、回滚、暂存或提交与当前任务无关的用户改动。
- 用户没有要求提交时，不自行 commit。
- 用户要求提交时，先检查 `git status` / diff，确认本次任务应包含的文件，再提交。
- 优先显式暂存目标文件，避免无条件使用 `git add .`。
- `reset --hard`、`clean`、强制 checkout、amend、force push 等可能破坏历史或工作区的操作，必须得到明确授权。

提交信息应准确描述实际变更，不需要额外的多轮确认；存在混杂改动或提交范围不明确时再询问。

## 构建与打包

仅当用户要求交付可执行产物、安装包或发布版本时执行。

- 使用项目现有构建方式；
- 产物与源码、缓存和临时文件分离；
- 需要分发时验证目标环境，而不是只验证开发机；
- 多进程/多运行时应用要确保依赖随正式交付方案可用，不把开发环境假设转嫁给用户。

## 完成标志

用户能够明确知道本次结果、验证状态和剩余风险；用户要求的额外交付动作已完成或明确说明未完成原因。
