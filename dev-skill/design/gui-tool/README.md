# 桌面 GUI 路线

仅用于**全新桌面工具**或用户明确要求调整桌面架构时。已有项目优先保持现有结构。

## 默认路线

```text
前端 UI
  ↓
Wails Binding / Adapter
  ↓
Go 业务与控制层
  ↓
文件、数据库、系统能力或可选 Python Worker
```

- Wails + Go 负责应用生命周期、系统集成和业务编排。
- 前端技术栈跟随项目；新项目优先选择当前稳定、主流的 TypeScript 前端方案，不在 Skill 中锁定具体版本。
- 小项目允许保持简单结构，不为了“标准架构”提前拆很多层。
- 复杂度增长后再按业务能力拆包，避免单个 `App` 或根目录无限膨胀。

## 什么时候引入 Python Worker

只有 Python 在核心能力上有明显优势时才引入，例如成熟 AI/数据/科学计算生态、专有 SDK、模型驻留或需要隔离高资源任务。

如果 Go 能简单可靠地完成任务，保持纯 Go。

引入 Worker 时只守以下边界：

- Go 管理 Worker 的启动、退出、超时、取消和异常；
- 前端不直接调用 Python；
- IPC 使用清晰、可校验的结构化协议；
- 长驻 Worker 需要基本健康检查和异常退出处理；
- 正式分发不能默认用户已经配置好开发用 Python 环境。

进程模型、协议形态和目录结构按实际需求决定，不固定模板。

## 验证

使用项目已有方式验证：Go 业务测试、Wails 构建、前端构建，以及真正受影响的端到端路径。不要为了满足规范而给每一层强制增加测试或抽象。
