# 实现原则

> 流程阶段③。优先遵循项目自身规范；本文件只保留跨语言、跨框架仍有价值的约束。

## 必须遵守

- 修改只围绕当前需求，不夹带无关重构或技术栈迁移。
- 尊重项目现有命名、目录、依赖管理、错误处理和代码风格。
- 保持职责和依赖方向清晰，避免为了“分层”而增加没有收益的抽象。
- 新增依赖、后台进程、持久化或公共 API 时必须有明确必要性。
- 对外行为变化时同步相关调用方、类型/协议定义和已有文档。
- 文件、数据库和外部服务操作要考虑失败后的状态一致性；高风险写操作优先可恢复方案。

## 代码质量

- 优先写清晰代码，不追求模式数量和目录层级。
- 消除真正有维护风险的重复和硬编码，不机械追求“零重复”。
- 注释解释非显而易见的原因、约束和取舍，不逐行翻译代码。
- 错误信息应帮助定位问题；需要时处理超时、取消和资源释放。
- 不手工修改应由生成器、代码生成或构建流程维护的产物。

## 已有项目保护

- 不覆盖、回滚或格式化与当前任务无关的用户改动。
- 大范围删除、替换或自动格式化前先确认影响范围。
- 如果发现额外问题，记录并说明；除非会阻塞当前任务，不自动扩大修复范围。

## 完成标志

实现满足方案且改动范围受控后，进入 [验证阶段](testing.md)。
